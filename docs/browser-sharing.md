# 浏览器共享

主机运行 Nocturne 与已经授权的 Pianoteq，浏览器只是琴键控制器和声音接收端。它不会获得本机管理权限，也不需要安装钢琴音源。

## 本机与局域网

在桌面程序右上角打开“浏览器共享”，默认端口 **18982**。点击开启后生成一条含 `/#key=…` 的邀请链接，再点击“本机浏览器试听”。网页需要主动点击“进入琴房”，才能解除浏览器自动播放限制。

默认仅监听 `127.0.0.1`，适合把穿透客户端运行在同一台电脑。要直接从局域网访问，请关闭共享、勾选“允许局域网访问”，重新开启，在 Windows 防火墙允许 Nocturne 的专用网络入站，并将链接里的 `127.0.0.1` 换成主机的局域网 IPv4 地址。不要使用 WSL 或虚拟网卡地址。

## 你后续配置内网穿透时

| 项目 | 配置 |
| --- | --- |
| 本地目标 | `http://127.0.0.1:18982` |
| 公网入口 | 你自己的 HTTPS 域名 |
| WebSocket | 必须支持 `/ws` 的 Upgrade，并保留原始 Host / Origin |
| 子路径 | 放在域名根路径，暂不支持 `/piano/` 子路径 |
| 邀请 | 替换邀请链接的域名部分，保留 `/#key=…` |
| WebRTC | STUN 默认已填；复杂网络可填 TURN |

**不要穿透 Pianoteq 的 18981 端口。** 该端口是本地管理接口，浏览器服务不依赖远程用户直接访问它。

反向代理需要允许长连接，关闭代理缓冲；例如 Nginx 在此域名的 `location /` 中配置 `proxy_pass http://127.0.0.1:18982;`、`proxy_http_version 1.1;`、`proxy_set_header Host $http_host;`、`proxy_set_header Upgrade $http_upgrade;`、`proxy_set_header Connection "upgrade";`、`proxy_buffering off;`、`proxy_read_timeout 3600s;`。TLS 证书与域名由你的穿透服务配置。

访问密钥在 URL fragment 中，不发送到网页请求 URL，只用于 WebSocket 身份验证。页面载入后会从地址栏移除密钥；重新刷新或重新打开页面请使用完整原始邀请链接。关闭共享后旧链接失效，重新开启需要重新分享。

## 声音通道

- **WebRTC**：Opus 双声道 48 kHz，目标 192 kbps，10 ms 音频包。音频一次编码后共享给连接；浏览器使用自己的抖动缓冲。STUN 用于尝试直连，TURN 用于中继。
- **网页备用通道**：无法建立 WebRTC 时使用 WebSocket 传输 PCM16 双声道，净负载约 1.54 Mbps/人。有界队列和播放缓冲会丢弃过旧样本，避免延迟不断累积。TCP 丢包重传仍可能造成卡顿。
- **输入**：DataChannel 优先，WebSocket 备用。定期发送完整按键状态；无更新超过约 1.2 秒时释放该访问者的琴键，关闭连接也会释放。同一个音由多人按住时保留引用计数。

所有访问者听到的是同一个 Pianoteq 输出，包括主机演奏、MIDI 自动播放和其他访问者的琴键。远程演奏使用 MIDI 第 16 通道；若你的 MIDI 也使用此通道，建议自动播放时只聆听，以避免相同音符互相影响。

网页不请求麦克风，不使用屏幕共享。主机采集通过 Windows 进程回环锁定提供本地 18981 服务的 Pianoteq 进程。另一个程序的音乐、通知和聊天不会被纳入采集。此功能与 F9 离线渲染录音独立；录制时远程用户只能聆听。

## 排错

| 现象 | 检查 |
| --- | --- |
| 页面能打开但连接失败 | 是否保留了邀请密钥，是否开启 WebSocket，代理是否保留 Host；共享是否已重新开启导致密钥失效 |
| 手机没有声音 | 点击进入琴房；从后台回来时点击恢复声音；检查手机媒体音量 |
| 连接正常、始终没钢琴声音 | Pianoteq 是否使用 Windows Audio 共享输出，输出设备是否正常；ASIO 和独占模式改用共享模式 |
| 主机提示音频中断 | 重新连接 Pianoteq，然后关闭并重新开启共享；音源重启会改变进程 ID |
| 一直显示网页通道 | 直连未成功；HTTP 穿透并不提供 UDP 音频中继，需要自行配置可用 TURN |
| 声音有明显延迟 | 检查网页网络 RTT、主机上行带宽和 TURN 地理位置，关闭蓝牙耳机，降低 Pianoteq 本机音频缓冲 |
| 开启时缺少运行时 | 安装 .NET 8 Desktop Runtime 与 ASP.NET Core Runtime 8 的 x64 版本 |

本机 Chromium/Edge 自动化已验证 WebRTC 实际音频、WebSocket/AudioWorklet 实际音频、手机尺寸多指触控、无越界布局、失联松键、同音多用户、鉴权拒绝与录制锁定。外网穿透、真实 iPhone/Android 硬件和你的 TURN 服务需要在配置后实际验证，不能由本机测试代替。
